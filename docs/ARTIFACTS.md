# Artifact and appendix convention

`output/` is raw machine-readable evidence. `reports/` is a generated index plus manually reviewed feasibility material. **Neither directory is committed to GitHub**; back up both. Never share raw HAR files publicly.

## PoC (not an autonomous agent run)

```text
output/poc/
  stage-manifest.json
  task-inputs/284.json
  284/
    accessibility/01.yaml
    inspection.json
    inspection.har
reports/poc/
  poc-review.md            # manual PASS / MODIFY / REJECT checklist
  stage-summary.md
  artifact-index.csv
  artifact-index.json
```

Inspection HAR intentionally has a different filename from the official agent HAR. `network.har` must only contain a complete agent run, paired with `agent_response.json` and official `eval_result.json`.

## Pilot (6 tasks × 4 models × 2 methods)

```text
output/pilot/
  stage-manifest.json
  task-inputs/<task-id>.json
  <task-id>/
    accessibility/01.yaml
    inspection.json
    inspection.har
  runs/
    <model>/
      baseline/<task-id>/
        agent_response.json
        network.har
        eval_result.json
      proposed/<task-id>/
        agent_response.json
        network.har
        eval_result.json
reports/pilot/
  task-screening.csv       # manual inclusion criteria; never overwritten
  artifact-index.csv
  artifact-index.json
  stage-summary.md
  pilot-run-index.csv      # generated by pilot:gate AFTER evaluated agent runs
  pilot-gate.json
  pilot-gate.md
```

`npm run artifacts:init -- --stage pilot` creates all 48 empty run directories and the task-screening template; it does not fabricate successful runs or invoke models. `npm run pilot:gate` checks the official results and emits an operational provisional gate. Without run artifacts it correctly fails.

## Main (32 held-out Shopping tasks × 4 models × 2 methods)

```text
output/main/<experiment-id>/
  stage-manifest.json
  runs/<model>/<baseline|proposed>/<task-id>/
  summary/
reports/main/<experiment-id>/
  artifact-index.csv
  artifact-index.json
  stage-summary.md
```

Main scaffold checks that there are exactly 32 distinct task IDs, none reused from the six development/pilot tasks, and all exist in an official public Shopping catalog. This does **not** replace independent inclusion screening, approval, frozen parameters, the future autonomous runner or statistical analysis.

Only after main runs exist should we add and validate: per-run metadata (model digest, quantization, temperature, budget, seed, browser/Docker/evaluator versions, git commit, freeze hash), complete run summaries, paired result tables and the final Bab IV statistical exports.

## Operational commands

```powershell
npm.cmd run artifacts:init -- --stage poc
npm.cmd run webarena:prepare -- --task 284 --stage poc
npm.cmd run webarena:inspect -- --task 284 --stage poc
npm.cmd run artifacts:report -- --stage poc

# Only after PoC approval:
npm.cmd run artifacts:init -- --stage pilot

# Only after the 48 pilot agent runs have official eval_result.json:
npm.cmd run pilot:gate
```

The indexes are derived reports, not ground truth. A reviewed checklist/CSV is preserved on repeated initialization. An evidence source or run result is never silently replaced by report generation.

## Extended evidence capture and Colab analysis

The PoC inspector also saves \`output/poc/284/screenshots/start-01.png\`, with a relative \`screenshot_file\` field in \`inspection.json\`.

The development agent produces \`output/{poc|pilot}/runs/<model>/<baseline|proposed>/<task-id>/\` containing:

```text
run_metadata.json        # UUID, task/model/method, benchmark version, budget, timing
trace.jsonl              # one auditable, publicly grounded decision/final event per step
accessibility/0001.yaml  # visible accessibility snapshot, repeated per step
screenshots/initial.png
screenshots/decision-0001.png  # at most three meaningful probe checkpoints
screenshots/final.png
agent_response.json      # model's claim, not the evaluator result
network.har              # Playwright agent run, not inspection
eval_result.json         # written by official CLI only if evaluated
```

The official-results exporter creates `run-inventory.csv` (all 48 or 256 expected cells), `analysis-results.csv` (technically valid, evaluated cells only), and `analysis-summary.md` in the stage report directory. The notebook `notebooks/thesis_analysis.ipynb` reads the two CSVs, refuses confirmatory main tests for incomplete coverage, and exports thesis-ready plots and tables.

**Do not commit raw evidence or upload HAR to Colab**. See `docs/EVIDENCE_PROTOCOL.md`.
